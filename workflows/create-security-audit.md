# Анализ безопасности по ГОСТ 5131 (из удалённого репозитория)

Этот workflow анализирует репозиторий по указанному URL: клонирует его, выполняет анализ по ГОСТ и сохраняет результат в папку `results/`. Для работы с файлами используется MCP server-filesystem.

## Структура файлового хранилища

| Назначение       | Путь                                                                 |
|------------------|----------------------------------------------------------------------|
| План анализа 5.1 | `docs/plans/Анализ текущего состояния процессов разработки безопасного ПО.md` |
| Шаблон 5.1       | `docs/templates/Анализ текущего состояния процессов разработки безопасного ПО.md` |
| План 5.3         | `docs/plans/Регламент управления требованиями безопасности (п.5.3 ГОСТ).md` |
| Шаблон 5.3       | `docs/templates/Регламент управления требованиями безопасности (п.5.3 ГОСТ).md` |
| ГОСТ Р 56939-2024| `docs/standarts/ГОСТ Р 56939— 2024.md`                 |
| Результат 5.1    | `results/{repo-name}/Анализ текущего состояния процессов разработки безопасного ПО.md` |
| Результат 5.3    | `results/{repo-name}/Регламент управления требованиями безопасности ПО.md` |

## Инструкция по выполнению

### 1. Запросить адрес репозитория

Спроси пользователя URL репозитория для анализа (GitHub, GitLab и т.п.). Примеры форматов:
- `https://github.com/org/repo-name`
- `https://github.com/org/repo-name.git`
- `https://gitlab.com/org/repo-name`

Извлеки имя репозитория из URL (например, `repo-name` из `https://github.com/org/repo-name.git`).

### 2. Клонировать репозиторий

- Репозиторий для анализа должен находится в корне пользователя, не в `mcp/server-dib/`
- Создай в корне пользователя папку `repos-for-analysis`, если её нет.
- Выполни: `git clone <url> repos-for-analysis/<repo-name>`
- Если при клонировании возникла ошибка с доступом к репозиторию, попробуй еще 3 раза с промежутком в пять секунд, до первого удачного клонирования
- Если клонирование все-таки не удалось — сообщи пользователю об ошибке и не переходи к следующим шагам.

### 3. Прочитать план и выполнить анализ

- Прочитай детальный план из `docs/plans/Анализ текущего состояния процессов разработки безопасного ПО.md`
- Ознакомься с примером: `docs/templates/Анализ текущего состояния процессов разработки безопасного ПО.md`
- Выполни анализ **внутри** `repos-for-analysis/<repo-name>/`, следуя инструкциям из плана
- Создай папку `results/<repo-name>/` (если её нет) и сохрани итоговый документ как `results/<repo-name>/Анализ текущего состояния процессов разработки безопасного ПО.md`

### 4. Запустить задачу 5.3 (Регламент управления требованиями безопасности) — новый таск

После успешного завершения п. 5.1 (анализ) **запусти новый таск** по п. 5.3:

- Прочитай план из `docs/plans/Регламент управления требованиями безопасности (п.5.3 ГОСТ).md`
- Задача 5.3 **опирается на результат 5.1** из `results/<repo-name>/Анализ текущего состояния процессов разработки безопасного ПО.md`
- Выполни план 5.3: извлеки данные из результата 5.1, сформируй регламент и набор требований по ГОСТ 5.3.3.1 и 5.3.3.2
- Создай итоговый документ в `results/<repo-name>/Регламент управления требованиями безопасности ПО.md`

### 5. Удалить репозиторий

Удали папку `repos-for-analysis/<repo-name>` (через `rm -rf` или аналог), чтобы освободить место.
